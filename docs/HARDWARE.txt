================================================================================
ledd 2.0 - 硬件信息
================================================================================

【设备】
    机型：Lenovo L79031（拯救者电竞手机 Pro）
    系统：Android 10
    Root：Magisk
    SELinux：Permissive

【I2C】
    总线：/dev/i2c-6
    从机地址：0x5b
    必须用：I2C_SLAVE_FORCE
    禁止：unbind 驱动（会 kernel panic）

【LED 驱动：AW9106】
    寄存器布局（已验证）：
      0x11      亮度档
                0x00 最亮
                0x01 亮
                0x02 中
                0x03 正常（默认）
      0x12/0x13/0x14   初始化寄存器，只需写一次 0
      0x20/0x23  R
      0x21/0x24  G
      0x22/0x25  B

    两组寄存器（0x20~0x22 和 0x23~0x25）对应两组通道
    写相同值时两组显示同色

【I2C 地址自增（实测）】
    从 0x20 连续写 7 字节：
      {0x20, R, G, B, R, G, B}
    会依次写入 0x20~0x25
    自增到 0x22 后仍继续（实测覆盖 0x25）

    从 0x20 写 4 字节：
      {0x20, R, G, B}
    只写到 0x22，0x23~0x25 保持原值
     必须写满 7 字节才能覆盖两组

【初始化序列（只需一次）】
    0x12 = 0
    0x13 = 0
    0x14 = 0
    0x11 = 默认亮度（如 0）

【改色（每次）】
    一次 7 字节写：
      {0x20, R, G, B, R, G, B}
    仅 1 次 I2C 传输

【改亮度（运行时）】
    单独写 0x11：
      {0x11, bright}
    1 次 I2C 传输

【已验证的坑】
    1. 必须先 I2C_SLAVE_FORCE
    2. 0x12/0x13/0x14 必须初始化写一次
    3. 否则被 Android LED 驱动覆盖
    4. 写满 7 字节才能覆盖两组寄存器
    5. 不 unbind 驱动（kernel panic）
    6. 高频连续改色稳定（50 FPS 验证通过）

【性能】
    原方案：10 次 I2C 写 / 每次改色，约 2ms
    新方案：1 次 I2C 写 / 每次改色，约 0.15ms
    提升：约 10 倍
