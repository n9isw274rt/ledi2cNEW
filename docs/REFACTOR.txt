================================================================================
ledd - 新旧对比（重构前后）
================================================================================

【一、代码组织】
--------------------------------------------------------------------------------
旧：
    单个 ledd.c，约 500 行
    所有逻辑混在一起

新：
    10 个模块
      main / i2c / socket / command / effect / source
      audio / timer / log / util
    effect 拆成 9 个文件（主逻辑 + 7 效果 + 头文件）

收益：
    改一个效果只动一个文件
    加新效果 = 加文件 + 表项
    好读、好测、好维护

【二、I2C 写入】
--------------------------------------------------------------------------------
旧：
    每次改色写 10 次 I2C：
      0x12 0x13 0x14 0x11 0x20 0x21 0x22 0x23 0x24 0x25
    约 2ms/次
    50 FPS 下每帧花 10% 时间在 I2C

新：
    初始化写一次：0x12 / 0x13 / 0x14 / 0x11
    每次改色写 1 次：
      {0x20, R, G, B, R, G, B}  (7 字节)
    约 0.15ms/次
    50 FPS 下每帧花 0.75%

对比：
    传输次数：10  1
    数据字节：20  7
    耗时：约 10 倍提升

【三、主循环】
--------------------------------------------------------------------------------
旧：
    select + usleep(20000)
    每 20ms 必醒一次
    空闲时也有 50 次/秒唤醒
    off 模式用 2 秒 select 超时省 CPU

新：
    epoll_wait(-1) 无限阻塞
    timerfd 按需启停
    空闲时真 0%
    无 usleep

对比：
    空闲唤醒：50 次/秒  0
    空闲 CPU：有   0%
    定时精度：usleep（ms 级） timerfd（µs 级）

【四、timerfd 管理】
--------------------------------------------------------------------------------
旧：
    无 timerfd 概念
    靠主循环周期 + sleep

新：
    EffectOps.need_timer 标记
    规则：timerfd 跑 = (source == MIC) && (effect need_timer)
    effect_set_mode / source_set 都触发重评估

触发场景：
    E_OFF           停
    E_STATIC        停（设色时写一次）
    source=system   停
    动态效果 + mic  跑

对比：
    新增能力：切 source 自动停 timerfd（旧版无此逻辑）
    旧版隐患：动态效果 + system 会两个路径抢灯
    新版：明确不抢

【五、socket】
--------------------------------------------------------------------------------
旧：
    单客户端（或靠"每次重连"绕抢占）
    每次 send 都 connect + close
    App 每秒 50 次命令 = 每秒 100 次 syscall 建/断连接

新：
    多客户端长连接（上限 8）
    每 client 独立行缓冲（512 字节）
    一次 recv 多行，逐行返回
    非阻塞

对比：
    syscall：150+/秒  100/秒
    连接稳定性：更好
    App 侧简化：不用每次重连
    audiohook 侧：本来已长连接，不变

【六、命令解析】
--------------------------------------------------------------------------------
旧：
    parse_cmd 里一大串 if (strcasecmp(...))
    加命令改一大堆

新：
    命令表：
      { "STATIC", cmd_static },
      { "BREATH", cmd_breath },
      ...
    加命令只加一行表项

【七、效果引擎】
--------------------------------------------------------------------------------
旧：
    主循环里 switch (mode)
      case E_BREATH: ...
      case E_RAINBOW: ...
    加效果要改主循环

新：
    EffectOps 表：
      [E_BREATH] = { "breath", 1, enter, tick, NULL },
    每个效果独立文件
    主循环只调 effect_tick
    加效果不改主循环

【八、AUDIO 处理】
--------------------------------------------------------------------------------
旧：
    AUDIO mode 1~5
    base 色  强度映射
    状态：g_baseR/G/B、g_peakR/G/B、g_lastRms
    SET:base / SET:peak 命令
    source != 2 判断

新：
    audio_handle(args) 就一行：
      sscanf(args, "%d,%d,%d", &r,&g,&b)
      effect_output(r,g,b)
    无状态、无映射、无判断
    删 SET:base / SET:peak

对比：
    代码：约 30 行  7 行
    状态：3 组  0
    audiohook 侧：只发 mode 5（发 RGB）

【九、source】
--------------------------------------------------------------------------------
旧：
    mic / system / off 三个值
    off 隐含关灯 + 切源

新：
    mic / system 两个值
    off 从 source 移除
    OFF 独立命令（只管 effect，不动 source）

对比：
    职责更清晰
    OFF 和 source 解耦

【十、文件通道】
--------------------------------------------------------------------------------
旧：
    socket + 文件（led_rgb.txt）双通道
    每 100ms 轮询文件
    fopen/fgets/fclose

新：
    只保留 socket
    删除文件通道
    删除 100ms 轮询

对比：
    减少 syscall
    减少 CPU
    少一个需要维护的路径

【十一、配置模块】
--------------------------------------------------------------------------------
旧：
    ledd_config.txt 读写
    save_config / load_config
    SOURCE / SET 命令触发写文件

新：
    全删除
    配置不持久化
    重启回默认

说明：
    配置改由 App 侧管理
    App 启动时重新发一遍命令即可

【十二、初始化流程】
--------------------------------------------------------------------------------
旧：
    i2c_open
    load_config
    setup_socket
    开机呼吸动画（1 秒）
    write_rgb(0,0,0,3)
    主循环

新：
    log_init
    i2c_init（含寄存器初始化）
    socket_init
    timer_init
    source_init / effect_init / command_init
    epoll_create
    注册 listen_fd / timer_fd / signal_fd
    主循环

对比：
    删除开机动画（1 秒等待）
    删除配置加载
    启动更快

【十三、退出处理】
--------------------------------------------------------------------------------
旧：
    Ctrl+C 靠 signal 简单处理
    可能不清理

新：
    signalfd 塞进 epoll
    收到 SIGINT/SIGTERM 后统一 cleanup：
      timer_stop / socket_close / i2c_close
    资源释放干净

【十四、日志】
--------------------------------------------------------------------------------
旧：
    fprintf(stderr, ...) 到处
    无级别

新：
    LOGD / LOGI / LOGW / LOGE
    带时间戳、模块名
    编译时可关（改 log_init 的级别）

【十五、性能数据】
--------------------------------------------------------------------------------
指标               旧              新           提升
I2C 传输/改色      10 次           1 次         10 倍
I2C 字节/改色      20              7            约 3 倍
空闲 CPU 唤醒      50 次/秒        0            
空闲 CPU 占用      有               0%         
静态色 I2C 写      每帧重复        只写一次     
启动时间           含 1 秒动画     ~几十 ms     
二进制大小         （旧版更大）    35KB         
内存占用           约 33MB VIRT    33MB VIRT    相当

【十六、保留不变的部分】
--------------------------------------------------------------------------------
AW9106 寄存器地址：0x11 / 0x12-0x14 / 0x20-0x25
I2C_SLAVE_FORCE
不 unbind 驱动
socket 路径 /data/local/tmp/ledd.sock
协议风格（命令:参数）
效果视觉算法（曲线、软边、smoothstep）
颜色数学（hsv2rgb）
source 语义（mic / system）

【十七、重构收益汇总】
--------------------------------------------------------------------------------
性能：
    - I2C 快 10 倍
    - 空闲 CPU 归零
    - 定时更精准（ABSTIME）

架构：
    - 插件式效果
    - 命令查表
    - 事件驱动
    - 分层清晰

可维护：
    - 10 个模块，每个职责单一
    - 加效果 3 步
    - 改命令 1 行
    - 单元测试友好

稳定性：
    - 多客户端不抢
    - source 切换自动停 timerfd
    - 压力测试通过
    - 无 E/W 日志
